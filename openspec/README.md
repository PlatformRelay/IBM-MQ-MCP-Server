# Specification workflow

This repository follows an OpenSpec-style proposal workflow:

- `changes/<change-id>/proposal.md` states intent and boundaries.
- `changes/<change-id>/design.md` captures technical design after foundational
  decisions are approved.
- `changes/<change-id>/tasks.md` tracks scenario-mapped implementation work.
- `specs/` becomes the canonical behavior specification when an approved change
  is implemented and archived.

Roadmap stories link to these artifacts rather than copying their requirements.
