# MSG-003 — Separately gated destructive consume

**Status:** Open · lane/msg-003  
**Authority:** `openspec/changes/safe-messaging/proposal.md`

## Outcome

Profiles granted `consume` destructively retrieve bounded messages with
truthful delivery semantics distinct from browse.

## Acceptance

- Consume requires its own capability; `browse` alone can never remove a
  message, proven by test.
- Count and wait-interval maxima are server-enforced; empty-queue behavior is
  deterministic and documented.
- Delivery semantics claim only what mqweb Messaging REST truthfully provides
  (no syncpoint or exactly-once claims).
- A denied consume makes no MQ call; e2e proves depth decreases only on
  consume.
