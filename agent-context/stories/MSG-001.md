# MSG-001 — Prove mqweb message semantics and ship bounded browse

**Status:** Blocked by message semantics  
**Authority:** `openspec/changes/safe-messaging/proposal.md`

## Outcome

Verified mqweb Messaging REST semantics gate the messaging contract, and
approved profiles browse bounded messages non-destructively without payload
leakage.

## Acceptance

- A recorded spike against live MQ (FND-004) documents mqweb browse
  destructiveness, get semantics, supported payload formats, and limits.
- Browse requires the `browse` capability and is a separate operation and
  policy check from consume and produce.
- Count, wait interval, and payload bytes have safe server-enforced maxima.
- Results identify truncation, encoding, and message identifiers; payload
  inclusion is opt-in.
- Binary and malformed payload behavior is deterministic.
- Payload logging is prohibited; configured redaction applies before results.
- Tests prove browse does not remove messages — or browse is not shipped.
- Produce is [MSG-002](MSG-002.md); destructive consume is
  [MSG-003](MSG-003.md).

## Decisions and open questions

- ADR-0002 restricts the first release to mqweb Messaging REST. Unsupported
  message semantics are deferred rather than emulated.
- Payload defaults, formats, limits, and redaction (design questions 14–16).
