# CON-001 — Resolve multiple secure MQ connection profiles

**Status:** Open — ADR-0004 Accepted  
**Authority:** `openspec/changes/connection-profiles-and-policy/proposal.md`

## Outcome

Operators configure multiple independently authenticated IBM MQ profiles and
select one explicitly for every remote operation.

## Acceptance

- Profiles have stable names and validate endpoint, queue-manager identity,
  TLS, authentication, timeout, and secret references at startup.
- TLS verification defaults on; custom CA and approved mTLS flows work.
- Environment and mounted-file secret references are supported in this slice;
  further providers are [CON-002](CON-002.md).
- Credentials are resolved only when needed and never appear in logs/results.
- Connection clients are pooled per profile and shut down cleanly.
- One failing profile does not prevent healthy profiles from being used unless
  strict startup is explicitly selected.
- Tests cover duplicate names, missing secrets, invalid TLS, authentication
  failure, timeout, and profile isolation.

## Decisions and open questions

- [ADR-0002](../../docs/adr/0002-mqweb-first-connectivity.md) selects mqweb
  Administrative and Messaging REST APIs behind typed ports; PCF/native is
  deferred.
- First-release authentication methods and secret providers ([ADR-0004](../../docs/adr/0004-configuration-and-secrets.md)).
- Startup versus lazy validation — fail-open default; `--strict-startup` opt-in (ADR-0004).
